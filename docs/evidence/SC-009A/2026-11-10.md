## Protocol basis

Reviewed Deepgram's official [interim and endpoint guide](https://developers.deepgram.com/docs/understand-endpointing-interim-results), [endpointing example](https://developers.deepgram.com/docs/endpointing), [interim results](https://developers.deepgram.com/docs/interim-results), [utterance-end reference](https://developers.deepgram.com/docs/utterance-end), [streaming API reference](https://developers.deepgram.com/reference/speech-to-text/listen-streaming), [diarization](https://developers.deepgram.com/docs/diarization), and [reconnect guidance](https://developers.deepgram.com/docs/recovering-from-connection-errors-and-timeouts-when-live-streaming-audio). They distinguish finalized text from speech endpointing; the endpointing example also shows a non-final result with a speech endpoint. The utterance-end documentation shows `[0,1]` for mono and a `-1` stale sentinel; the streaming API example shows `[0]`, so both documented mono forms are accepted. Interim examples omit `speech_final`; absence is treated as no endpoint, while an invalid present value is rejected.

Deepgram does not document a unique result event ID or guarantee a stable start value for every revision. The implementation's exact provider-start association is a conservative local policy scoped to session, source and stream epoch, not a provider identity guarantee. It explicitly rejects ambiguous overlapping windows or changed finals rather than merging them based on text or sample-rounded timestamps.

## Limitations and remaining work

This block adds a normalizer, not a live `IStreamingTranscriber` implementation, connection manager, configured model, retry policy or actual Deepgram integration. SC-009B/C retain those tasks and their verification. The mixed-speaker case does not preserve per-word speaker keys: it retains the original text unattributed and reports degraded attribution. SC-009B tracks fuller provenance without rewriting text. A caller must forward source capture gaps and handle normalization failures without silently discarding final records; this synthetic block does not prove the future transport or durable reducer does so.

The normalizer is single-owner per connection, with bounded message, segment, event and sent-interval state. Mapping never silently creates support for an unconfirmed send. A final whose entire time range is unsupported and a partial whose timing spans disjoint intervals fail explicitly because the current Core records cannot safely represent those cases. Identity association remains a documented provider-dependent limitation, and overlapping ambiguity is surfaced. No actual provider quality, latency, hardware, or phase gate is established by this evidence.
