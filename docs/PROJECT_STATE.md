# Current project context

Updated November 27, 2026. Architecture baseline 0.1. Task and gate status lives only in [backlog.json](../tasks/backlog.json).

Sidecue currently has a minimal WPF shell, an overlay prototype, separate Windows microphone and playback capture adapters, a session lifecycle coordinator, and a synthetic contract replay. Audio, providers and persistence are not connected to the shell or lifecycle. Overlay screen sharing and physical audio behavior are not fully verified.

SC-004B adds an infrastructure storage adapter with a random key protected by current-user DPAPI, user-restricted storage under `%LocalAppData%/SidecueData`, explicit recovery failures and an identity-checked SQLCipher loader. The reviewed native DLL is in ignored local build artifacts. Startup must own SQLitePCL initialization and deployment must protect the native library's containing directories from untrusted modification before app wiring.

The [SC-004B evidence](evidence/SC-004B/2026-11-09.md) records a same-user process restart, concurrent live-WAL reopen, protected permissions, invalid keys, interrupted initialization, modified native DLL rejection and synthetic plaintext scans. The locked Release build and 153 existing tests passed; the focused probe passed after the final loader guard. Earlier [SC-004A evidence](evidence/SC-004A/2026-11-08.md) records the native candidate and canary. These results do not establish clean-VM, packaged-binary or portable-recovery behavior.

The [SC-004C local preflight](evidence/SC-004C/2026-11-10-preflight.md) adds a repeatable synthetic durability probe. Abrupt child-process termination immediately before/after write and migration commits passed recovery, FTS and integrity checks on the current Windows profile. A disposable clean Windows environment was not established, so the leaf remains blocked; its [clean-run procedure](evidence/SC-004C/clean-environment.md) and remaining actions are recorded. The native rebuild recipe is disabled pending a verified Windows Perl toolchain patched for CVE-2026-15534. The reviewed existing DLL remains available for hash-checked testing.

SC-007 adds an application lifecycle coordinator with separate capture/generation states, immediate pause/end/recovery fences, context epochs and idempotent terminal effects. The [SC-007 evidence](evidence/SC-007/2026-11-10.md) records the 21 fake-backed lifecycle cases and affected test results. Its effect seam is not yet wired to devices, providers, UI or durable session storage. Integration must satisfy the nonblocking fence, inert capture lease, atomic finalization and publication requirements in [service contracts](CONTRACT_SERVICES.md); SC-010, SC-012 and SC-016 track the corresponding work. An uncooperative durable-start write can delay End, though capture remains fenced and disposal is bounded.

SC-009A/B provide a Deepgram normalizer and `IStreamingTranscriber` adapter. Each source has a separate socket, bounded retry and drain, and an independent timing map per speech epoch. Mixed-speaker results preserve available word-level attribution and the original text. The locked build and 85 affected tests passed with local fake sockets and synthetic audio. The actual provider and configured model still require SC-009C verification. SC-010A owns capture integration, including protected credential resolution, routed capture gaps and disjoint speech epochs. SC-008B owns durable speaker provenance. [Normalization evidence](evidence/SC-009A/2026-11-10.md) · [Transport evidence](evidence/SC-009B/2026-11-27.md)
