### SC-001A

**Define identity, timing and immutable event records**

Type: implementation. Dependencies: SC-000. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Read CONTRACTS.md identity/time, audio ownership, transcript events and answer events sections.

**Scope**

- Implement the minimal typed session/source/epoch/sequence/revision/request values and immutable capture, transcript and answer records described by CONTRACTS.md.
- Define audio buffer ownership and validate intervals, sample counts and contract versions without native capture.

**Acceptance**

- Invalid identity, revision or time-range combinations fail explicitly; UTC history time and monotonic ordering cannot be substituted.
- Records preserve source identity, timeline/stream epochs and answer request fencing; owned buffers have deterministic disposal semantics.

**Focused checks**

- Unit-test invalid IDs/ranges, epoch separation, sample-to-duration rounding and disposal on representative transfer/rejection paths.

**Stop boundary / excluded work**

- No capture, provider, database, lifecycle controller or production transcript reducer.

Owned areas: `src/Sidecue.Core/`, `tests/Sidecue.Core.Tests/Contracts/`.

Parent coverage: scope 1; acceptance 2; validation 2.

### SC-001B

Type: implementation. Dependencies: SC-000, SC-001A. Gates: none. Interactive Windows evidence: not required by this leaf.

- Add the capture/transcriber/store/clock/assistance interfaces and immutable command/context envelopes needed by the initial replay.

**Focused checks**

- Verify contract construction retains versions and immutable request metadata.

### SC-001C

**Add deterministic fakes and the first replay runner**

Type: implementation. Dependencies: SC-000, SC-001B. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-001A/B contracts compile; synthetic fixture inputs only.

**Scope**

- Implement controllable clock, capture, transcription, assistance and persistence fakes, plus one repeatable replay entry point.
- Use fictional fixtures to replay duplicate/reordered partial-final events, stream resets and obsolete answers against the contract invariants.

**Acceptance**

- The same fixed fixture yields the same normalized observations without hardware, network, keys or wall-clock sleeps.
- Invalid/reused conflicting identities are rejected, partial/final distinctions survive replay, and late answers remain associated with their original session/epoch/request.

**Focused checks**

- Run the fixed replay twice and compare results; cover duplicate, reordered, partial/final, reset and late-answer cases.
- Record the fixture format and contract mapping, keeping reference-model behavior distinct from future production reconciliation.

**Stop boundary / excluded work**

- No real provider/native capture; production lifecycle, persistence reconciliation and request scheduling remain later tasks.

Owned areas: `tests/Sidecue.Replay.Tests/`, `tests/fixtures/`, `tools/replay.ps1`.

Parent coverage: scope 2; acceptance 1, 2, 3; validation 1, 2.
