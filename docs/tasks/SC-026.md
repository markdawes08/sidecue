### SC-026A

**Fence deleted content out of active and queued work**

Type: implementation. Dependencies: SC-021, SC-024, SC-025. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Existing durable job fencing, source identities and context/retrieval cache boundaries.

**Scope**

- Create durable deletion tombstones and cancel related generation/indexing work before removing content.
- Invalidate scoped in-memory retrieval/context caches and recheck tombstones at job publication and request assembly.

**Acceptance**

- After deletion starts, cached or late provider/job results cannot reintroduce the target into prompts, search or regenerated notes.
- Existing unrelated content and jobs remain usable.

**Focused checks**

- Deterministically interleave deletion with generation, indexing and cache reads; verify stale completion is rejected at persistence and presentation boundaries.

**Stop boundary / excluded work**

- Physical row/backup purge and retention scheduling are SC-026B; do not claim provider-side deletion.

Owned areas: `src/Sidecue.Application/Retention/`, `src/Sidecue.Application/`, `src/Sidecue.Infrastructure/Persistence/`, `tests/Sidecue.Infrastructure.Tests/Retention/`.

Parent coverage: scope 2; acceptance 1; validation 1, 2.

### SC-026B

**Purge retained data with restartable deletion jobs**

Type: implementation. Dependencies: SC-021, SC-024, SC-025, SC-026A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-026A deletion barriers; encrypted storage; app-managed backup policy from DATA_AND_RECOVERY.md even before the later backup UI.

**Scope**

- Implement bounded, idempotent purge/retention jobs for transcripts, artifact versions, chunks, vectors, FTS, source references, queued jobs and app-managed backups.
- Expose the deletion policy and distinguish app-managed data from user exports and provider-retained content.

**Acceptance**

- Interrupted deletion resumes without dangling references; all managed representations cease exposing the target, including backup expiry or recreation.
- The UI does not promise secure SSD erasure, external export removal or provider-side deletion.

**Focused checks**

- Interrupt and resume a retention job; search every managed representation and verify backup policy plus SC-026A cache invalidation.
- Run the deletion-during-index/generation regression cases against the completed purge path.

**Stop boundary / excluded work**

- Portable recovery, external backup management and vendor deletion APIs are excluded; stop after the documented managed-data policy is enforced.

Owned areas: `src/Sidecue.Application/Retention/`, `src/Sidecue.Infrastructure/Persistence/`, `src/Sidecue.Desktop/`, `tests/Sidecue.Infrastructure.Tests/Retention/`.

Parent coverage: scope 1, 3; acceptance 1, 2, 3; validation 1, 2.
