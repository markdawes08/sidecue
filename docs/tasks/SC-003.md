### SC-003A

**Acquire separate microphone and loopback streams**

Type: implementation. Dependencies: SC-001. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-001 contracts; Windows WASAPI environment and selected maintained wrapper/native bindings.

**Scope**

- Implement WASAPI shared microphone and render-loopback sources behind the capture contracts.
- Keep callback work to bounded frame transfer, source/timing metadata and deterministic buffer/resource ownership.

**Acceptance**

- Microphone and remote frames retain separate source identities; callbacks contain no network, inference, SQL or dispatcher waits.
- Opening/stopping/disposing releases devices and abandoned buffers without intentional audio files.

**Focused checks**

- Adapter tests cover open failure, stop/dispose before enumeration and callback ownership; run a short local source probe without retaining audio.

**Stop boundary / excluded work**

- No normalization pipeline, device-reopen policy or speech provider integration.

Owned areas: `src/Sidecue.Windows/Audio/`, `tests/Sidecue.Windows.Tests/Audio/`.

### SC-003B

**Normalize audio with bounded queues and gap-aware timing**

Type: implementation. Dependencies: SC-001, SC-003A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-003A frame source and ownership contract; controllable clock/fake frames from SC-001.

**Scope**

- Normalize each source on worker threads into the initial provider format, with duration/byte queue bounds.
- Dispose dropped unsent frames and coalesce gaps. Add a platform-independent sent-sample interval helper driven by confirmed or uncertain transport-send outcomes, never by queued/normalized frames alone.

**Acceptance**

- Slow consumers cannot make callback work or buffered audio unbounded; overflow preserves source/epoch and gap boundaries.
- Provider-relative positions map back to original supported session intervals; a dropped middle interval never shifts later transcript time backward.
- The shared timing helper uses no Windows/provider SDK types; unsent audio cannot advance provider time, and uncertain sends remain marked uncertain.

**Focused checks**

- Use deterministic overload and dropped-middle-interval replays to check queue limits, disposal, gap accounting and uncertainty for discontinuous spans.

**Stop boundary / excluded work**

- No connection/reconnect transport, physical device transitions or silent audio replay.

Owned areas: `src/Sidecue.Windows/Audio/`, `tests/Sidecue.Replay.Tests/Audio/`, `src/Sidecue.Application/Timing/`.

Parent coverage: scope 2; acceptance 3; validation 1, 3.

### SC-003C

**Recover invalidated audio devices with explicit epochs**

Type: implementation. Dependencies: SC-001, SC-003B. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-003A/B capture and bounded normalization; fake endpoint notifications.

**Scope**

- Detect source invalidation/default-device changes and implement bounded reopen behavior.
- Allocate a new stream epoch, preserve the session timeline and expose the discontinuity or failed recovery.

**Acceptance**

- A reopened source cannot reuse the old stream identity or silently substitute another source.
- Stop/cancel during reopen terminates promptly; uncertainty and known gaps survive recovery.

**Focused checks**

- Use deterministic endpoint-change/reopen failures and stop races; verify new epochs, visible gaps and complete resource release.

**Stop boundary / excluded work**

- No process-tree selection, Bluetooth matrix, speakerphone AEC or two-hour endurance run.

Owned areas: `src/Sidecue.Windows/Audio/`, `tests/Sidecue.Windows.Tests/Audio/`, `tests/Sidecue.Replay.Tests/Audio/`.

Parent coverage: scope 3; acceptance 2, 3; validation 1, 3.

### SC-003D

**Verify real two-source capture and device transitions**

Type: verification. Dependencies: SC-001, SC-003C. Gates: none. Interactive Windows evidence: required.

**Prerequisites**

- SC-003A-C complete; interactive Windows, working microphone/playback endpoints, USB headset and synthetic remote playback.

**Scope**

- Run a synthetic headset meeting with separate microphone and playback, then remove/reconnect USB and change default endpoints.
- Record only source/epoch/timing/gap and queue measurements, not raw meeting audio.

**Acceptance**

- Physical capture yields distinct sources; device changes create explicit discontinuities and new epochs.
- No intentional audio file is produced; observed queue/callback behavior agrees with the bounded implementation.

**Focused checks**

- Execute the relevant physical AUD cases and verify source labels, resource release, new stream epochs and gap reporting.
- Link deterministic overload/timestamp results from prior leaves instead of rerunning unrelated suites.

**Stop boundary / excluded work**

- No untested headset/device support claims or broad release audio matrix; corrective defects receive bounded follow-up work.

Owned areas: `docs/evidence/SC-003D/`, `docs/WINDOWS_TEST_MATRIX.md`.
