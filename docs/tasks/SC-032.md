### SC-032A

**Create consistent encrypted snapshots during activity**

Type: implementation. Dependencies: SC-004, SC-012, SC-026, SC-031. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Validated SQLCipher build, serialized writer, DPAPI key store and implemented retention/deletion policy.

**Scope**

- Use the validated encrypted backup API to snapshot committed state while WAL is active, without plaintext intermediate files.
- Store backup/key material outside installer directories and apply existing access, retention and deletion policies.

**Acceptance**

- A snapshot taken during writes represents a consistent committed state and retains required key/schema metadata.
- Backups remain encrypted and follow app-managed expiry/recreation policy; original-profile dependence is explicitly described.

**Focused checks**

- Run native encrypted-store tests with active WAL writes, interrupted snapshot creation and synthetic canaries; verify integrity and encryption of successful snapshots.

**Stop boundary / excluded work**

- Restore UI and physical reinstall/profile evidence are SC-032B/C; portable passphrase export is excluded.

Owned areas: `src/Sidecue.Infrastructure/Backups/`, `tests/Sidecue.Infrastructure.Tests/Backups/`.

Parent coverage: scope 1, 2, 3; acceptance 1; validation 1.

### SC-032B

**Restore snapshots with explicit data and key safeguards**

Type: implementation. Dependencies: SC-004, SC-012, SC-026, SC-031, SC-032A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-032A encrypted snapshots and controlled test stores/keys; documented recovery policy.

**Scope**

- Implement same-profile restore validation and a recovery flow that preserves an explicit rollback path.
- Check key availability, encryption, integrity, schema compatibility and retention/deletion rules before replacing data; require explicit handling of newer local data.

**Acceptance**

- Wrong, absent or corrupt key/backup fails clearly with no plaintext fallback or silent data replacement.
- The restore flow labels original-profile dependency and cannot bypass deletion policy or promise lost-profile portability.

**Focused checks**

- Test valid restore, corrupt snapshot, missing/wrong key, incompatible schema, newer local data and interrupted replacement with an explicit rollback plan.

**Stop boundary / excluded work**

- Cross-profile physical proof and upgrade/reinstall evidence are SC-032C; no portable export design.

Owned areas: `src/Sidecue.Infrastructure/Backups/`, `src/Sidecue.Desktop/Views/Recovery/`, `tests/Sidecue.Infrastructure.Tests/Backups/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 2.

### SC-032C

**Verify recovery across WAL, upgrades and Windows profiles**

Type: verification. Dependencies: SC-004, SC-012, SC-026, SC-031, SC-032B. Gates: none. Interactive Windows evidence: required.

**Prerequisites**

- SC-032A/B; interactive Windows with disposable profiles, reviewed installer/update artifacts and an isolated synthetic database/key set.

**Scope**

- Restore snapshots from active WAL and after upgrade or ordinary reinstall in the original usable Windows profile.
- Demonstrate missing/corrupt key and lost-profile limitations using disposable test profiles, and verify the documented rollback plan.

**Acceptance**

- Restored committed data is consistent, encrypted and policy-compliant in the original profile.
- Lost-profile/key cases fail honestly; no portable recovery or silent replacement of newer data is claimed.

**Focused checks**

- Execute the bounded backup/restore matrix with synthetic stores, recording original-profile success, wrong/missing-key failures and post-upgrade/reinstall outcomes.
- Compare restored content, key location, retention effects and rollback observations; track failed cases as scoped corrective work.

**Stop boundary / excluded work**

- Do not delete a real user profile or use production meeting data; portable passphrase recovery remains deferred.

Owned areas: `docs/evidence/SC-032C/`, `tests/Sidecue.Infrastructure.Tests/Backups/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
