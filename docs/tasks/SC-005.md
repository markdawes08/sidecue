### SC-005D

**Build the in-memory screenshot approval preview**

Type: implementation. Dependencies: SC-000, SC-002B. Gates: none. Interactive compatibility evidence belongs to SC-005C.

**Prerequisites**

- SC-002B window policy, an interactive Windows desktop and synthetic pixel fixtures.

**Scope and acceptance**

- Add a disposable frame for tightly packed BGRA32 pixels. Validate dimensions and storage length before accepting ownership.
- Display a preview in an owned WPF dialog with Include and Cancel. Include transfers the same frame. Dismissal and cancellation release it.
- Request affinity for the preview HWND and show the Windows API result. Keep the pixel buffer in memory for the preview lifetime.

**Focused checks**

- Test frame bounds and release, exact preview pixels, explicit inclusion, dismissal and cancellation through the WPF dialog.

**Stop boundary**

### SC-005A

**Capture one selected target into an explicit preview**

Type: implementation. Dependencies: SC-000, SC-002B, SC-005D. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-005D approval preview and an interactive Windows desktop for the system picker and selected-target API probe.

**Scope**

- Use Windows.Graphics.Capture and the system picker to acquire a single bounded in-memory screenshot lease.
- Connect the captured frame to the SC-005D Include/Cancel preview.
- Validate the allocation with `OwnedScreenshotFrame.GetByteCount`, then copy the selected frame into tightly packed BGRA32 pixels. Pass ownership to `ScreenshotPreviewWindow.ShowAsync` and dispose an included frame after the prototype check.

**Acceptance**

- Target selection retains native identity, including same-resolution displays; cancellation yields no approved image.
- Capture and preview dispose rejected/replaced buffers and create no screenshot cache or file.

**Focused checks**

- Test picker cancellation, preview cancellation, explicit inclusion and lease disposal through synthetic capture boundaries; perform a local picker smoke check.

**Stop boundary / excluded work**

- No provider upload, automatic capture or request integration; those belong to SC-023.

Owned areas: `src/Sidecue.Windows/ScreenCapture/`, `src/Sidecue.Desktop/Prototypes/ScreenCapture/`, `tests/Sidecue.Windows.Tests/ScreenCapture/`.

Parent coverage: scope 1, 2; acceptance 1, 2; validation 2.

### SC-005B

**Handle screenshot target changes and resource failures**

Type: implementation. Dependencies: SC-000, SC-002B, SC-005A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-005A selected-target capture and lease ownership; fake capture failures.

**Scope**

- Handle resize, target closure, cancellation races and device loss around the single-frame capture/preview lifecycle.
- Verify that all active displays are in SDR before starting capture and again before handing the frame to the preview. The picker does not expose a reliable display ID for every selected target. An active HDR or Advanced Color display, an unknown mode, or an unexpected pixel format ends the request with a visible reason.
- A resized or closed target or lost graphics device requires a new selection. A completed capture is an immutable snapshot for the existing Include/Cancel preview.

**Acceptance**

- Lost/closed targets produce a visible failure or explicit reselection; no first-monitor fallback occurs.
- Every failure/cancel path releases frame pools and image leases; unsupported formats are reported rather than mislabeled.

**Focused checks**

- Use focused device-loss, resize, unsupported-format and cancellation fakes to check outcomes and disposal.

**Stop boundary / excluded work**

- No image generation, persistent media, broad graphics compatibility claim or provider vision wiring.

Owned areas: `src/Sidecue.Windows/ScreenCapture/`, `tests/Sidecue.Windows.Tests/ScreenCapture/`.

Parent coverage: scope 3; acceptance 1, 2, 3; validation 2.
