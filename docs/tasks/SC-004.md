### SC-004A

**Select and prove the native encrypted database build**

Type: implementation. Dependencies: SC-000. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Windows x64; an available native distribution whose use/redistribution basis can be recorded without invented credentials.

**Scope**

- Select and pin a distributable SQLCipher native build with Microsoft.Data.Sqlite.Core; record exact loaded native versions, provenance and license basis.
- Build a minimal encrypted FTS/WAL canary probe and confirm the required SQLite WAL fix or documented backport.

**Acceptance**

- The actual loaded native library supports encryption and FTS; no compatible build means a blocker, never plaintext fallback.
- Wrong/no key cannot read the canary, and tested database/WAL/temporary artifacts do not expose its plaintext.

**Focused checks**

- Run correct/wrong-key and FTS probes, inspect native SQLCipher/SQLite versions and scan the synthetic canary artifacts.

**Stop boundary / excluded work**

- No production transcript schema, persistent key lifecycle or installer; no purchasing/distribution-license choice beyond authorized evaluation.

Owned areas: `src/Sidecue.Infrastructure/Persistence/`, `tests/Sidecue.Infrastructure.Tests/Encryption/`, `docs/evidence/SC-004A/`, `docs/DEPENDENCIES.md`.

### SC-004B

**Protect database keys and reopen user storage**

Type: implementation. Dependencies: SC-000, SC-004A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-004A validated native build; Windows current-user DPAPI and a disposable synthetic test data directory.

**Scope**

- Generate random database keys and protect them with current-user DPAPI and user-restricted ACLs.
- Place keys/database under SidecueData outside installer-owned paths and implement same-user reopen plus explicit missing/corrupt-key failures.

**Acceptance**

- Same-user restart opens the encrypted store; absent/unusable protected keys fail clearly without creating a plaintext substitute.
- Keys never enter logs, command lines or checked-in settings, and ordinary data paths remain independent of installer location.

**Focused checks**

- Test create/reopen, wrong/missing/corrupt key, permissions and data-path selection under the actual Windows user.
- Implement a fail-closed production native loader using the reviewed SQLCipher binary identity; the SC-004A canary is not a production loader and system SQLite is not a fallback.

**Stop boundary / excluded work**

- No portable recovery, backup product, transcript schema or install/uninstall implementation.

Owned areas: `src/Sidecue.Infrastructure/Security/`, `src/Sidecue.Infrastructure/Persistence/`, `tests/Sidecue.StorageProbe/`.

Parent coverage: scope 2; acceptance 1, 2; validation 1.

### SC-004C

**Verify encrypted durability and clean-environment loading**

Type: verification. Dependencies: SC-000, SC-004B. Gates: none. Interactive Windows evidence: required.

**Prerequisites**

- SC-004A/B complete; disposable clean Windows x64 VM/profile with synthetic data and the reviewed native binaries.

**Scope**

- Exercise interrupted transactions and a small migration lifecycle with encryption and FTS/WAL enabled.
- Repeat native loading, wrong-key, reopen, FTS and canary-artifact checks in a clean Windows test environment.

**Acceptance**

- Reopening preserves committed state and migration consistency; encryption stays active across the tested journal/temp paths.
- Clean Windows loading uses the reviewed native distribution, with exact versions and same-profile key limitations recorded.

**Focused checks**

- Interrupt write/migration boundaries, reopen and check integrity; record clean-environment correct/wrong-key/FTS results and loaded native versions.
- Validate the reviewed binary in the clean environment and revalidate each distinct rebuild. The native rebuild recipe is disabled until a Windows Perl toolchain patched for CVE-2026-15534 is verified. SC-006A owns the eventual package's exact binary and SQLCipher/OpenSSL notices.
- Verify the deployment directory is protected against untrusted changes and startup exclusively owns SQLitePCL initialization before the storage adapter is wired into the application. The loader's path checks alone cannot eliminate concurrent directory substitution.

**Stop boundary / excluded work**

- No production-schema migration acceptance, portable DPAPI claim or release installer; report unavailable environment as pending evidence.

Owned areas: `tests/Sidecue.DurabilityProbe/`, `tools/probe-durability.ps1`, `docs/evidence/SC-004C/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
