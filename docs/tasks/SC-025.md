### SC-025A

**Browse searchable meeting history and source evidence**

Type: implementation. Dependencies: SC-022, SC-024. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Working history/retrieval and artifact services from upstream tasks; Windows WPF test environment.

**Scope**

- Connect existing retrieval to history search and transcript/source navigation; distinguish original transcript quotes from generated artifacts.
- Virtualize large result/transcript lists and keep retrieval/index work off the dispatcher.

**Acceptance**

- Search results retain meeting/document IDs, versions and evidence locations; navigation opens the intended source.
- A large synthetic history remains navigable while session controls remain responsive.

**Focused checks**

- UI/integration checks cover source navigation, empty results and a fixed large-history replay; measure dispatcher responsiveness for that case.

**Stop boundary / excluded work**

- Note editing and export belong to SC-025B/C; do not replace retrieval algorithms or redesign the dashboard.

Owned areas: `src/Sidecue.Desktop/Views/History/`, `tests/Sidecue.Ui.Tests/History/`.

Parent coverage: scope 1, 3; acceptance 2; validation 1.

### SC-025B

**Edit note versions without losing generated provenance**

Type: implementation. Dependencies: SC-022, SC-024, SC-025A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-025A navigation and existing SC-024 artifact version/retry behavior.

**Scope**

- Add note editing and version selection using the existing generated/user-edited artifact model.
- Preserve source links and separate user edits from later generation attempts.

**Acceptance**

- A saved user edit survives reopening and regeneration; version selection retains the correct origin and evidence.
- Saving or switching versions cannot silently overwrite a newer user-edited version.

**Focused checks**

- Run focused UI/storage checks for edit/save/restart, version selection and regeneration while an edited note exists.

**Stop boundary / excluded work**

- Export behavior is SC-025C; do not change the durable generation worker or introduce collaborative editing.

Owned areas: `src/Sidecue.Desktop/Views/Notes/`, `tests/Sidecue.Ui.Tests/History/`.

Parent coverage: scope 1; acceptance 1; validation 1.

### SC-025C

**Export selected meeting and note versions reliably**

Type: implementation. Dependencies: SC-022, SC-024, SC-025B. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-025B note-version selection and a test-controlled export directory.

**Scope**

- Export text, Markdown and transcript formats to an explicitly selected destination using existing versioned content.
- Keep evidence/completeness markers and user corrections in exported output; report completion only after the write succeeds.

**Acceptance**

- The exported selected version matches persisted edits after restart and regeneration.
- Cancelled, denied, full-disk or interrupted writes are not reported as successful exports.

**Focused checks**

- Use synthetic edited notes/transcripts for format checks and failed-destination integration tests; verify the selected version rather than exact incidental formatting.

**Stop boundary / excluded work**

- External sharing, message sending and new document formats are excluded.

Owned areas: `src/Sidecue.Infrastructure/Exports/`, `src/Sidecue.Desktop/Views/History/`, `src/Sidecue.Desktop/Views/Notes/`, `tests/Sidecue.Ui.Tests/History/`.

Parent coverage: scope 2; acceptance 1, 3; validation 1.
