### SC-017A

**Connect the overlay command bar and streamed answer view**

Type: implementation. Dependencies: SC-002, SC-011, SC-016. Gates: G0. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- The prototype overlay, dashboard commands and request coordinator are implemented; Windows WPF test execution is available.

**Scope**

- Replace prototype bindings with view models using the existing session controller and request coordinator.
- Render streamed answer states and route Clear context, Hide, Pause listening and End through their distinct application commands.

**Acceptance**

- Rapid requests and late events cannot make the view display another request's answer or confuse partial/failed/completed states.
- Each control invokes the intended application behavior; hiding the overlay does not pause capture or end a session.

**Focused checks**

- Use focused UI/view-model tests for rapid requests, clear during streaming, hide/show and pause/end routing.
- Check keyboard access to current controls using synthetic coordinator events without live providers.

**Stop boundary / excluded work**

- No new session/request rules, hotkey customization, monitor-placement persistence or native sharing proof.

Owned areas: `src/Sidecue.Desktop/Views/Overlay/`, `src/Sidecue.Desktop/ViewModels/Overlay/`, `tests/Sidecue.Ui.Tests/Overlay/`.

Parent coverage: scope 1, 3; acceptance 1; validation 1.

### SC-017B

**Integrate hotkeys, focus modes and monitor placement**

Type: implementation. Dependencies: SC-002, SC-011, SC-016, SC-017A. Gates: G0. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Integrated command/answer overlay and prior native focus/exclusion capability implementations are available.

**Scope**

- Add customizable and disableable hotkeys with explicit conflict reporting, plus deliberate interactive and non-activating overlay modes.
- Persist monitor placement by actual target identity and apply established exclusion/hide handling to all owned auxiliary windows.

**Acceptance**

- Streaming display does not request keyboard focus; entering question input is an explicit action.
- Conflicting hotkeys report failure, disabled bindings do nothing, and missing monitors use a documented visible placement policy without false capture protection.

**Focused checks**

- Test saved/disabled/conflicting bindings and focus-mode changes, including keyboard-only entry and dismissal.
- Exercise placement restore and auxiliary-window policy with supported monitor fixtures; preserve native-observation requirements for the following verification child.

**Stop boundary / excluded work**

- No expanded sharing compatibility claim or redesign of the prototype's exclusion API boundary.

Owned areas: `src/Sidecue.Windows/Hotkeys/`, `src/Sidecue.Desktop/Views/Overlay/`, `src/Sidecue.Desktop/ViewModels/Overlay/`, `tests/Sidecue.Ui.Tests/Overlay/`.

Parent coverage: scope 2; acceptance 1, 2, 3; validation 1.

### SC-017C

**Verify focus and sharing behavior of the integrated overlay**

Type: verification. Dependencies: SC-002, SC-011, SC-016, SC-017B. Gates: G0. Interactive Windows evidence: required.

**Prerequisites**

- Interactive Windows desktop, supported meeting client/share mode, a receiving observer, and required monitor setup are available.

**Scope**

- Repeat physical focus and baseline observer-side screen-share checks using the actual integrated overlay controls and auxiliary windows.
- Record exact client/OS/display configuration and immediate hide behavior for unsupported or failed exclusion.

**Acceptance**

- Typing in the meeting client remains uninterrupted during answer streaming, while intentional Sidecue input works.
- Every supported tested surface follows the recorded exclusion policy and a reliable hide path; untested or failed scenarios remain explicit.

**Focused checks**

- Run keyboard-only commands, rapid requests, hide/show and clear-context checks while sharing synthetic content.
- Record the receiving participant's view for baseline share paths, auxiliary windows and representative monitor/DPI movement.

**Stop boundary / excluded work**

- No full phase-4 compatibility campaign or generic UI overhaul; create scoped corrective tasks for discovered failures.

Owned areas: `docs/evidence/SC-017C/`, `tests/Sidecue.Ui.Tests/Overlay/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
