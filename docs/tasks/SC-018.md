Complete one leaf per prompt, including its focused checks and handoff. Check upstream dependencies, gates and the listed external prerequisites before claiming it. Stop after that leaf; do not automatically start its sibling. A completed child does not complete the parent.

Coverage numbers below refer to the parent backlog arrays, counting from 1. They distribute the work; they do not substitute for evidence. Update this card and the backlog together when scope changes.

### SC-018A

**Implement the four manual assistance actions**

Type: implementation. Dependencies: SC-014, SC-016, SC-017. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Profiles, immutable snapshots, request coordinator and integrated overlay commands are ready.

**Scope**

- Implement Ask, Suggest what to say, Follow-up questions and Recap as explicit actions using current immutable snapshots and concise versioned templates.
- Keep supplied evidence and insufficient context distinguishable; action text cannot authorize external execution or sending.

**Acceptance**

- Each request records its action, profile version and model configuration and consumes only the selected current snapshot.
- Missing or ambiguous context produces an honest insufficient-context path rather than an invented meeting fact.

**Focused checks**

- Replay short fictional technical and governance examples through fake generation responses.
- Test action metadata, empty context and unsupported factual claims with the fixed action rubric.

**Stop boundary / excluded work**

- No automatic suggestions, usage UI, live-model defaults or new coordinator behavior.

Owned areas: `src/Sidecue.Application/Actions/`, `prompts/actions/`, `tests/Sidecue.Application.Tests/Actions/`.

Parent coverage: scope 1, 3; acceptance 1, 2; validation 1, 2.

### SC-018B

**Expose profile, detail and usage state in the overlay**

Type: implementation. Dependencies: SC-014, SC-016, SC-017, SC-018A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- The four manual actions and provider usage events are implemented.

**Scope**

- Connect profile selection and optional detailed mode to subsequent manual requests.
- Display configured provider/model, optional reported usage totals and explicit partial/cancelled/failure states.

**Acceptance**

- Profile switches affect new requests while prior responses keep their recorded profile/model identity.
- Missing usage is shown as unknown rather than zero, and cancelled or partial output is never labelled complete.

**Focused checks**

- Test profile switching during a request, detailed-mode submission, unavailable usage and cancelled partial output.
- Check view-model bindings and keyboard access without a live provider.

**Stop boundary / excluded work**

- No cost estimates unsupported by configuration, provider-account management or visual redesign.

Owned areas: `src/Sidecue.Desktop/Views/Overlay/`, `src/Sidecue.Desktop/ViewModels/Overlay/`, `tests/Sidecue.Application.Tests/Actions/`.

Parent coverage: scope 2; acceptance 1, 3; validation 2.

### SC-018C

**Evaluate manual-action grounding on fixed fictional meetings**

Type: verification. Dependencies: SC-014, SC-016, SC-017, SC-018B. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Manual actions and their overlay metadata/status presentation are complete, with versioned fictional evaluation cases available.

**Scope**

- Run the four actions against fixed short technical/governance fixtures with explicit evidence-support and usefulness rubrics.
- Record results for unclear questions, missing context, unsupported claims, profile changes and absent usage.

**Acceptance**

- Each evaluated answer can be traced to its fixture, action/profile/model configuration and supplied snapshot.
- Unsupported facts and inaccurate completion/usage labels fail the evaluation; unresolved failures remain visible and prevent parent closure.

**Focused checks**

- Use deterministic provider fixtures to verify action behavior and record rubric judgments without exact-wording assertions.
- Preserve disputed or missing facts rather than treating fluent output as a pass; live model selection remains SC-019.

**Stop boundary / excluded work**

- No live model tournament or unrelated prompt refinement; create bounded corrective children for failures.

Owned areas: `tests/Sidecue.Application.Tests/Actions/`, `docs/evidence/SC-018C/`, `prompts/actions/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
