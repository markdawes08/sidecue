### SC-023A

**Bind an approved screenshot lease to one assistance request**

Type: implementation. Dependencies: SC-005, SC-015, SC-016, SC-017. Gates: G0. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Selected-target capture prototype, generation capabilities, request coordinator and integrated overlay are ready.

**Scope**

- Connect the selected-target preview to the request snapshot with an explicit Include/Send approval bound to both image and request identity.
- Honor provider vision capability and transfer/dispose bounded image leases through completion, cancellation, replacement and failure.

**Acceptance**

- Cancelling preview sends no image, and neither session change nor request replacement can attach that image to another request.
- Target closure/capture failure and unsupported vision preserve a visible usable text-only path.

**Focused checks**

- Use mock transport to assert image presence/absence by request ID for approve, cancel, supersede and session-change cases.
- Test disposal on every terminal path and bounded buffers without writing screenshot files.

**Stop boundary / excluded work**

- No new screen-capture engine, automatic screenshots or live image-provider evaluation.

Owned areas: `src/Sidecue.Application/ScreenContext/`, `src/Sidecue.Desktop/Views/ScreenPreview/`, `tests/Sidecue.Application.Tests/ScreenContext/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1.

### SC-023B

**Verify approved-image behavior on real Windows targets**

Type: verification. Dependencies: SC-005, SC-015, SC-016, SC-017, SC-023A. Gates: G0. Interactive Windows evidence: required.

**Prerequisites**

- Interactive Windows capture environment and synthetic target windows are available; a controlled transport observer can verify image routing without real private data.

**Scope**

- Exercise the integrated picker/preview/approval flow against real synthetic-content windows and monitors.
- Observe cancellation, resizing, target closure and request changes while checking transport metadata and temporary-file behavior.

**Acceptance**

- Only the explicitly approved image can be present for its intended request; cancelled previews produce no upload.
- Failure paths remain text-only and usable, and no persistent screenshot artifact is created.

**Focused checks**

- Run real Windows target selection, preview, resize/close and cancellation cases with synthetic content.
- Combine receiving transport assertions with buffer/disposal observations and temporary-file inspection; record the exact environment.

**Stop boundary / excluded work**

- No private screenshots, expanded capture support matrix or unlimited corrective work.

Owned areas: `docs/evidence/SC-023B/`, `tests/Sidecue.Application.Tests/ScreenContext/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
