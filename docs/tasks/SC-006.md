### SC-006A

**Produce a repeatable self-contained development package**

Type: implementation. Dependencies: SC-000, SC-004. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-004 native encryption proof; official supported packaging tooling and reviewed distribution notices.

**Scope**

- Add a pinned Velopack packaging entry point for the minimal shell and reviewed native encryption dependencies.
- Produce self-contained win-x64 development artifacts and record their dependency/trust configuration.

**Acceptance**

- The package is built by a documented command and contains its required managed/native runtime inputs.
- Unsigned artifacts are visibly development-only; no release-signing or publication claim is made.

**Focused checks**

- Build and inspect one development package for required binaries, architecture, version and exclusion of agent/source/evidence/private files.
- Include the applicable SQLCipher and OpenSSL notices and verify the installed native-library directory is protected from untrusted modification. Validate the exact DLL shipped; a source-tree ACL is not installed-package evidence.
- If rebuilding the native dependency, first select and verify a Windows Perl toolchain patched for CVE-2026-15534, update the disabled build recipe and validate the exact resulting DLL.

**Stop boundary / excluded work**

- No release update service, signing credential setup, publication or end-user compatibility certification.

Owned areas: `tools/package.ps1`, `packaging/`, `src/Sidecue.Desktop/Startup/`.

Parent coverage: scope 1, 3; acceptance 3; validation 2.

### SC-006B

**Separate installer files from durable user data**

Type: implementation. Dependencies: SC-000, SC-004, SC-006A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-006A package; SC-004 key/storage boundary; disposable synthetic user state.

**Scope**

- Make startup data/key/backup paths independent of Velopack RootAppDir/AppContentDir.
- Exercise a controlled development upgrade/uninstall path with synthetic encrypted state and protected keys.

**Acceptance**

- Normal upgrade/uninstall never targets SidecueData or its protected key; reopening after replacement preserves synthetic data.
- Path policy works without administrator assumptions and does not expose plaintext fallback or secrets.

**Focused checks**

- Add focused data-path and preservation tests; check packaged native encryption loading and an internal upgrade/uninstall cycle.
- Before wiring storage into startup, ensure that the application exclusively owns SQLitePCL provider initialization and that the verified native DLL is loaded from the protected installation directory.

**Stop boundary / excluded work**

- No separate delete-data command, signed update channel or portable backup feature.

Owned areas: `src/Sidecue.Desktop/Startup/`, `tests/Sidecue.Infrastructure.Tests/Paths/`, `packaging/`.

Parent coverage: scope 2, 3; acceptance 2, 3; validation 1, 2.

### SC-006C

**Verify installation and preservation as a standard user**

Type: verification. Dependencies: SC-000, SC-004, SC-006B. Gates: none. Interactive Windows evidence: required.

**Prerequisites**

- SC-006A/B complete; disposable clean Windows x64 machine/VM and standard-user account, with two development package versions.

**Scope**

- Install/start, upgrade, uninstall and reinstall the development package on clean Windows without developer tools.
- Verify retained synthetic encrypted data and key reopen under the original usable user profile.

**Acceptance**

- The standard user can install and start the self-contained shell with its native encryption library.
- Upgrade and ordinary uninstall preserve data/key outside installer directories; trust prompts and unsigned status are accurately recorded.

**Focused checks**

- Record the full clean-machine installation cycle, actual package hashes, account privilege level and native library load results.

**Stop boundary / excluded work**

- No public distribution, trusted-release assertion or unrelated updater hardening; keep failed scenarios pending.

Owned areas: `docs/evidence/SC-006C/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
