### SC-019A

**Prepare bounded model-comparison fixtures and measurements**

Type: implementation. Dependencies: SC-018. Gates: G1. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Manual-action evaluation and reliable integrated transcription are available; identify enabled test providers and cost/request constraints before execution.

**Scope**

- Define a small configured candidate set and fixed synthetic meeting cases for live/detailed assistance profiles.
- Instrument stage-separated capture, STT, retrieval, model and render measurements and usefulness/grounding/cost metadata.
- Record not-yet-implemented retrieval as not configured/unmeasured. Instrument the available stages without pulling SC-021/022 into this task.

**Acceptance**

- The evaluation procedure records model/configuration versions and a fixed rubric, request budget and stopping point.
- Stage samples can produce honest p50/p95 with errors, absent usage and warm/cold conditions included; preparation claims no selected winning model.

**Focused checks**

- Dry-run scoring and timing with deterministic fixtures, including unsupported claims and stale output.
- Check that output records contain synthetic evidence references and safe metadata, not credentials or real meeting content.

**Stop boundary / excluded work**

- No candidate execution, new providers or unbounded benchmark framework.

Owned areas: `tests/evals/`, `docs/evidence/SC-019A/`.

### SC-019B

**Run candidate evaluations and record model defaults**

Type: verification. Dependencies: SC-018, SC-019A. Gates: G1. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Configured live-test credentials, enabled provider/model access, approved synthetic cases and the prepared bounded evaluation procedure are available.

**Scope**

- Execute the prepared bounded comparison against explicitly configured candidate models and preserve result/configuration provenance.
- Select live/detailed defaults from measured usefulness, grounding, latency and available cost metadata, or leave selection unresolved with concrete reasons.

**Acceptance**

- Selected model IDs and settings have a recorded rationale tied to fixed fixtures and measured results.
- Each profile satisfies the stated rubric or its supported limitations are explicit; errors/timeouts and missing cost data are not dropped from the report.

**Focused checks**

- Compare candidate outcomes on the same cases, recording stage p50/p95, sample counts and test conditions.
- Review unsupported claims, citation support and stale-answer behavior instead of relying solely on model self-grading.

**Stop boundary / excluded work**

- No unrestricted candidate search, new provider routing or physical meeting demonstration in this slice.

Owned areas: `docs/evidence/SC-019B/`, `configuration/model-profiles.json`, `tests/evals/`, `prompts/`.

Parent coverage: scope 1, 2; acceptance 1, 2, 3; validation 1.

### SC-019C

**Demonstrate selected profiles in an end-to-end Windows meeting**

Type: verification. Dependencies: SC-018, SC-019B. Gates: G1. Interactive Windows evidence: required.

**Prerequisites**

- Interactive Windows environment, real capture devices, enabled configured providers and synthetic/authorized meeting participants are available.

**Scope**

- Exercise the chosen live/detailed configuration through real Windows capture, transcription, context, model streaming and overlay rendering.
- Demonstrate cancellation, deliberate focus entry and context continuity while retaining a redacted measurement/evidence report.
- Record not-yet-implemented retrieval as not configured/unmeasured. Instrument the available stages without pulling SC-021/022 into this task.

**Acceptance**

- No obsolete answer crosses request/session changes during the demonstration.
- Observed focus and continuity match the intended workflow; profile limitations and actual tested configuration remain explicit in evidence.

**Focused checks**

- Interleave new requests, Clear context, cancellation and session changes while measuring the stage-separated path.
- Record real device/provider conditions and p50/p95 samples, including failures; register bounded corrective children for any unmet original acceptance.

**Stop boundary / excluded work**

- No general compatibility matrix, unrelated UI polish or automatic model reselection.

Owned areas: `docs/evidence/SC-019C/`, `tests/evals/`.
