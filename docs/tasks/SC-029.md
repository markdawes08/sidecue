### SC-029A

**Preserve sessions through power and permission changes**

Type: implementation. Dependencies: SC-017, SC-023, SC-028. Gates: G0, G2. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Completed session lifecycle, capture recovery and permission-status contracts; Windows event/failure injection seams.

**Scope**

- Handle sleep/wake, lock/unlock and microphone permission changes through the existing lifecycle and recovery boundaries.
- Keep the session identity while invalidating and reopening affected audio streams with new epochs and explicit gaps.

**Acceptance**

- Resume after a power or lock transition retains the session identity and does not relabel a restarted stream as uninterrupted.
- Denied or withdrawn microphone permission produces an actionable recoverable state with no fabricated capture success.

**Focused checks**

- Run deterministic suspend/resume, lock/unlock and permission-revocation cases, including changes while starting or stopping; record physical cases still needed in SC-029C/D.

**Stop boundary / excluded work**

- Bluetooth, docking and GPU/device replacement are SC-029B; Home/Pro matrix evidence is SC-029C/D. Do not redesign the session state machine.

Owned areas: `src/Sidecue.Windows/`, `src/Sidecue.Application/`, `tests/Sidecue.Windows.Tests/`.

Parent coverage: scope 1; acceptance 1; validation none directly.

### SC-029B

**Recover from Bluetooth, docking and GPU device changes**

Type: implementation. Dependencies: SC-017, SC-023, SC-028, SC-029A. Gates: G0, G2. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-029A lifecycle recovery; existing process/audio selection, screenshot resources and window-exclusion status contracts.

**Scope**

- Handle Bluetooth endpoint/format changes, docking/undocking and GPU/display-device loss through the existing audio and windowing adapters.
- Reopen replaced streams with new epochs and gaps; invalidate capture-exclusion capability when windows/devices are recreated until the capability is re-established.

**Acceptance**

- Device replacement never silently changes the selected source or reuses an obsolete stream epoch.
- Unknown or failed screen exclusion after GPU/display recovery cannot retain a protected indicator; the hide path remains available.

**Focused checks**

- Exercise deterministic Bluetooth format/reconnect, dock monitor removal and GPU/device-loss events; verify source identity, disposal, gap reporting and capability invalidation.
- Run focused native adapter probes only where fakes cannot establish handler behavior; full physical support evidence remains SC-029C/D.

**Stop boundary / excluded work**

- Power/permission orchestration is owned by SC-029A; no new device support claims, general driver framework or full sharing matrix in this leaf.

Owned areas: `src/Sidecue.Windows/`, `src/Sidecue.Application/`, `tests/Sidecue.Windows.Tests/`.

Parent coverage: scope 1; acceptance 1, 2; validation none directly.
