### SC-027A

**Create editable follow-up drafts from selected evidence**

Type: implementation. Dependencies: SC-023, SC-025, SC-026. Gates: G2. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Existing note versions, deletion barriers, profile/context assembly and export services.

**Scope**

- Generate follow-up drafts using selected meeting evidence and a versioned profile template; reuse existing artifact editing and export services.
- Support copy/export or draft handoff with no automatic message transmission.

**Acceptance**

- Drafts preserve user corrections and evidence references; unsupported commitments, owners, recipients and dates remain unassigned or explicitly uncertain.
- Generating, copying or exporting a draft never sends a message.

**Focused checks**

- Evaluate fictional disputed decisions and missing recipients/dates; test edit preservation, repeated generation and absence of a send action.

**Stop boundary / excluded work**

- End-to-end workflow acceptance is SC-027B; email/CRM/calendar connections and automatic sending are excluded.

Owned areas: `src/Sidecue.Application/FollowUps/`, `src/Sidecue.Desktop/Views/FollowUps/`, `prompts/follow-ups/`, `tests/evals/follow-ups/`.

Parent coverage: scope 1, 2; acceptance 1, 2; validation 1.

### SC-027B

**Verify the complete grounded meeting-to-draft workflow**

Type: verification. Dependencies: SC-023, SC-025, SC-026, SC-027A. Gates: G2. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-027A integrated draft flow; deterministic providers and fictional corpus; completed parent upstream gates.

**Scope**

- Run a fixed fictional transcript-to-retrieval-to-notes-to-draft scenario set through the integrated application.
- Check source/version continuity, user edits, incomplete tails and deletion at the final draft boundary.

**Acceptance**

- Every generated factual commitment is supported by surviving selected evidence; incomplete or disputed content does not become a confident assertion.
- Deleted evidence cannot reappear through cached retrieval, notes or drafts; no message is sent during the workflow.

**Focused checks**

- Execute the agreed small fixture set containing disputed decisions, missing recipients/dates, incomplete transcripts and mid-work deletion; record evidence for each outcome.
- Create scoped corrective tasks for discovered defects and leave affected acceptance pending until targeted reruns pass.

**Stop boundary / excluded work**

- No open-ended model tuning, new integrations or unrelated UI fixes within this verification block.

Owned areas: `tests/evals/follow-ups/`, `docs/evidence/SC-027B/`.

Parent coverage: scope 3; acceptance 1, 2, 3; validation 1, 2.
