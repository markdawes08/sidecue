### SC-031A

**Apply updates only at safe session boundaries**

Type: implementation. Dependencies: SC-006, SC-012, SC-026. Gates: G0. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Existing packaging/update framework and lifecycle stop/drain semantics.

**Scope**

- Implement update discovery/download orchestration and defer application/restart until the session has stopped safely.
- Represent checking, available, downloaded, deferred and failed states without disrupting capture or losing pending work.

**Acceptance**

- An active or stopping meeting cannot be interrupted by automatic update/restart.
- Cancellation and download failure leave the current application usable and allow a bounded retry.

**Focused checks**

- Use deterministic update-source/session fakes to race update readiness with start, pause, stop and failure; confirm no apply/restart while the session is active.

**Stop boundary / excluded work**

- Trust/schema recovery is SC-031B and real signed upgrades are SC-031C; no auto-publication or new update service.

Owned areas: `src/Sidecue.Infrastructure/Updates/`, `tests/Sidecue.Infrastructure.Tests/Updates/`.

Parent coverage: scope 1; acceptance 1; validation none directly.

### SC-031B

**Validate update trust and recover compatible data safely**

Type: implementation. Dependencies: SC-006, SC-012, SC-026, SC-031A. Gates: G0. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-031A; documented update trust design, supported schema ranges and test fixtures that do not contain production signing secrets.

**Scope**

- Reject invalid release signatures or untrusted update sources; record trust failures without secrets.
- Handle failed application, schema compatibility/downgrade refusal and rollback limitations while preserving data; distinguish explicit delete-data from ordinary uninstall.

**Acceptance**

- Untrusted updates cannot be applied and unsupported newer schemas cannot be written by an older build.
- Failed update/recovery preserves available user data and keys; ordinary uninstall remains data-preserving.

**Focused checks**

- Test invalid/untrusted metadata, interrupted download/apply, supported upgrade and incompatible downgrade with synthetic stores and controlled update fixtures.
- Review package-input handling so signing/provider credentials cannot be included in produced artifacts.

**Stop boundary / excluded work**

- Actual signed standard-user lifecycle proof is SC-031C; no portable key recovery or automatic destructive rollback.

Owned areas: `src/Sidecue.Infrastructure/Updates/`, `tools/package.ps1`, `packaging/`, `tests/Sidecue.Infrastructure.Tests/Updates/`.

Parent coverage: scope 2, 3; acceptance 2, 3; validation 2.

### SC-031C

**Verify signed installation, upgrade and data preservation**

Type: verification. Dependencies: SC-006, SC-012, SC-026, SC-031B. Gates: G0. Interactive Windows evidence: required.

**Prerequisites**

- SC-031A/B; available authorized signing capability and trusted test update source; clean Windows standard-user environment and synthetic persisted data.

**Scope**

- Build reviewable signed test artifacts and exercise clean standard-user install, signed upgrade, interruption recovery, reinstall and ordinary uninstall.
- Check real certificate/source trust, schema/downgrade outcomes, data/key preservation and the separately explicit delete-data operation.

**Acceptance**

- Real signed updates succeed only for trusted inputs and do not interrupt an active session; untrusted or interrupted updates fail/recover as documented.
- Install/upgrade/reinstall/uninstall match data policy; no credential or private content is packaged.

**Focused checks**

- Run the finite lifecycle and interruption cases on a clean Windows environment, inspect package contents and record signature/trust observations.
- File bounded corrective tasks for failed cases and repeat only affected scenarios before accepting the lifecycle proof.

**Stop boundary / excluded work**

- No public publishing, infrastructure purchase or broad signing/account configuration beyond supplied authorized test capability.

Owned areas: `docs/evidence/SC-031C/`, `packaging/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1, 2.
