### SC-014A

**Persist immutable assistance profile versions**

Type: implementation. Dependencies: SC-001, SC-008. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Typed ProfileVersionId/configuration contracts and encrypted storage are available.

**Scope**

- Implement versioned prompt profiles and live/detailed response settings using the existing encrypted persistence boundaries.
- Make profile changes create a new version rather than mutating configuration referenced by earlier requests or artifacts.

**Acceptance**

- Loading a selected profile produces immutable settings with an explicit version ID.
- A profile edit changes subsequent selection while previously stored request/artifact references continue to identify their original version.

**Focused checks**

- Test create/edit/reload, invalid budgets and profile switching with deterministic storage fixtures.
- Verify earlier versions remain readable and logs omit profile bodies.

**Stop boundary / excluded work**

- No context assembly, model benchmarking or profile editor UI in this child.

Owned areas: `src/Sidecue.Infrastructure/Profiles/`, `src/Sidecue.Application/Context/`, `prompts/`, `tests/Sidecue.Application.Tests/Context/`.

### SC-014B

**Assemble bounded context with evidence provenance**

Type: implementation. Dependencies: SC-001, SC-008, SC-014A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Versioned profiles and typed transcript/evidence inputs are implemented; use a deterministic tokenizer/budget fixture and reviewed model capability configuration.

**Scope**

- Assemble recent finalized transcript, permitted provisional context, source-linked summary and evidence slots under the selected model's token budget.
- Count instructions/evidence and reserved output capacity; trim or compact derived context without modifying the durable transcript.

**Acceptance**

- Empty and long meetings produce a bounded context result with explicit omitted/provisional information and traceable summary sources.
- Clear-context boundaries exclude older same-session material from transcript, summary and evidence inputs; trimming never changes stored history.

**Focused checks**

- Test empty/long input, exact budget edges, oversized evidence and insufficient output reserve.
- Assert source references survive compaction and the persistent transcript is unchanged after trimming and clear-boundary assembly.

**Stop boundary / excluded work**

- No provider requests, real document retrieval algorithm or automatic suggestions; use supplied evidence through existing seams.

Owned areas: `src/Sidecue.Application/Context/`, `tests/Sidecue.Application.Tests/Context/`.

Parent coverage: scope 2; acceptance 1, 2; validation 1.

### SC-014C

**Freeze request snapshots across profile and epoch changes**

Type: implementation. Dependencies: SC-001, SC-008, SC-014B. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Versioned profiles, bounded context assembly and deterministic clock/store fixtures are ready.

**Scope**

- Create immutable request snapshots pinning transcript commit revision, context epoch, profile version, provider/model configuration and output budget.
- Reject stale assembly results when clear-context or session changes invalidate their inputs.

**Acceptance**

- Later transcript/profile edits cannot mutate a previously assembled snapshot or relabel an earlier artifact.
- Each accepted snapshot identifies exactly which evidence versions and limits produced the request; invalidated assembly cannot be submitted as current.

**Focused checks**

- Interleave profile switching, transcript commits and clear-context while assembly is pending.
- Check immutable collections/references, stale-epoch rejection and preserved output reservation without invoking a live provider.

**Stop boundary / excluded work**

- No foreground-request coordinator or UI event rendering; those remain with SC-016 and SC-017.

Owned areas: `src/Sidecue.Application/Context/`, `tests/Sidecue.Application.Tests/Context/`.

Parent coverage: scope 3; acceptance 1, 2, 3; validation 1.
