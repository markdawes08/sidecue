### SC-002A

**Create an overlay with honest exclusion capability reporting**

Type: implementation. Dependencies: SC-000. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Windows desktop for the real HWND/API probe; official window-affinity documentation.

**Scope**

- Create a minimal owned top-level WPF overlay and a narrow window-affinity adapter.
- Apply WDA_EXCLUDEFROMCAPTURE when the HWND is ready; surface result/error and provide an immediate hide path.

**Acceptance**

- Affinity success is reported as an API capability result, never proof of remote invisibility.
- Unsupported/failed exclusion is visible and hiding works without relying on a provider or meeting session.

**Focused checks**

- Exercise API success/failure through an injectable native boundary; verify HWND creation/recreation and hide behavior locally.

**Stop boundary / excluded work**

- No global-command customization, screen-share certification or production meeting UI.

Owned areas: `src/Sidecue.Windows/Windowing/`, `src/Sidecue.Desktop/Prototypes/Overlay/`, `tests/Sidecue.Windows.Tests/Windowing/`.

Parent coverage: scope 1; acceptance 2; validation none directly.

### SC-002B

**Implement overlay focus modes and keyboard controls**

Type: implementation. Dependencies: SC-000, SC-002A. Gates: none. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-002A overlay and capability reporting; Windows test environment for HWND interactions.

**Scope**

- Add separate non-activating display and deliberate interactive input modes, hide/show and bounded hotkey registration.
- Apply the same exclusion policy to auxiliary windows and preserve window identity during placement changes.

**Acceptance**

- Streaming display requests do not deliberately activate the overlay; keyboard entry is enabled only by the interactive path.
- Hotkey conflicts are surfaced; registrations/resources are released; auxiliary windows cannot silently bypass the exclusion policy.

**Focused checks**

- Focused window/command tests cover hide/show, input-mode transitions, failed registration and auxiliary-window policy.

**Stop boundary / excluded work**

- No saved user customization or broad compatibility claims; physical focus and observer evidence are later leaves.

Owned areas: `src/Sidecue.Windows/Windowing/`, `src/Sidecue.Desktop/Prototypes/Overlay/`, `tests/Sidecue.Windows.Tests/Windowing/`.

Parent coverage: scope 2, 3; acceptance 2, 3; validation 2.

### SC-002C

**Verify local overlay focus and monitor behavior**

Type: verification. Dependencies: SC-000, SC-002B. Gates: none. Interactive Windows evidence: required.

**Prerequisites**

- SC-002A/B complete; interactive Windows session, two monitors with mixed DPI, keyboard and a foreground application.

**Scope**

- Run the overlay against a real foreground application, then exercise two monitors, mixed DPI and monitor movement.
- Check deliberate text input, hotkey conflicts, hide/show, popups, tooltips and dialogs with metadata-only evidence.

**Acceptance**

- Observed non-activating updates preserve foreground focus; deliberate input remains usable.
- All exercised auxiliary surfaces retain the exclusion policy and a reliable hide path; untested configurations remain explicit.

**Focused checks**

- Record OS/build, display scaling and ordered focus/keyboard observations; run the relevant local cases in WINDOWS_TEST_MATRIX.md.

**Stop boundary / excluded work**

- No remote-share verdict from local screenshots or API return values; fixes larger than the observed case need a corrective task.

Owned areas: `docs/evidence/SC-002C/`, `tests/Sidecue.Windows.Tests/Windowing/`.

Parent coverage: scope 2, 3; acceptance 2, 3; validation 2.
