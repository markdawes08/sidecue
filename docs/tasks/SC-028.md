### SC-028A

**Select a process audio tree with explicit fallback**

Type: implementation. Dependencies: SC-013, SC-019. Gates: G1. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- Existing capture pipeline and native process-loopback APIs on the development Windows environment.

**Scope**

- Implement process-tree playback selection behind the Windows audio adapter.
- Require an explicit choice before system-audio fallback and describe browser-process scope accurately.

**Acceptance**

- A missing or unsupported selected process cannot silently widen capture to all system audio.
- Browser process selection never claims guaranteed isolation of one browser tab.

**Focused checks**

- Use adapter/control tests for selection, process exit, unsupported capture and fallback refusal/confirmation; retain source/epoch identities.

**Stop boundary / excluded work**

- Speakerphone/AEC evaluation and physical support claims belong to SC-028B/C; no custom audio driver.

Owned areas: `src/Sidecue.Windows/Audio/`, `src/Sidecue.Desktop/`, `tests/Sidecue.Windows.Tests/Audio/`.

Parent coverage: scope 1; acceptance 1, 2; validation none directly.

### SC-028B

**Expose speakerphone and echo-handling capability limits**

Type: implementation. Dependencies: SC-013, SC-019, SC-028A. Gates: G1. Interactive Windows evidence: not required by this leaf.

**Prerequisites**

- SC-028A selection; supported native capability documentation and a Windows environment for the narrow probe.

**Scope**

- Evaluate the supported platform AEC capability and wire explicit capability reporting for headset/speakerphone paths.
- Keep speaker/source labels anonymous unless assigned; preserve genuine repeated or overlapping speech instead of destructive text deduplication.

**Acceptance**

- Unavailable AEC or uncertain attribution has an honest user-visible state.
- No text filter discards legitimate repetition to simulate echo removal; supported behavior is configurable and measurable.

**Focused checks**

- Replay overlapping/repeated synthetic speech and unsupported AEC capability reports; inspect source attribution and content preservation.
- Record the chosen native capability and focused probe results without claiming a full device matrix.

**Stop boundary / excluded work**

- Physical headset/speakerphone acceptance is SC-028C; do not build a new echo-cancellation engine.

Owned areas: `src/Sidecue.Windows/Audio/`, `src/Sidecue.Application/Transcripts/`, `tests/Sidecue.Windows.Tests/Audio/`, `docs/evidence/SC-028B/`.

Parent coverage: scope 2, 3; acceptance 3; validation none directly.

### SC-028C

**Measure process and speakerphone capture on real devices**

Type: verification. Dependencies: SC-013, SC-019, SC-028B. Gates: G1. Interactive Windows evidence: required.

**Prerequisites**

- SC-028A/B; physical headset and speakerphone, multiple output endpoints, synthetic multi-speaker/tab audio and an interactive Windows session.

**Scope**

- Run the declared headset/speakerphone cases with multiple output devices, simultaneous speakers and browser audio from multiple tabs.
- Record included/excluded sources, echo/duplication measurements and tested limitations in the UI/support record.

**Acceptance**

- Process capture and fallback match the explicit selection; browser scope is described accurately.
- Speakerphone limitations are measured and user-visible, while overlap and legitimate repetition remain present.

**Focused checks**

- Execute the finite audio cases for the declared available devices and record OS, drivers, endpoints and outcomes; unavailable configurations remain pending.
- File bounded corrective tasks for failed cases; close this leaf only after required cases and targeted reruns have evidence.

**Stop boundary / excluded work**

- No wider device certification, new AEC algorithm or unrelated transcript refactor.

Owned areas: `docs/evidence/SC-028C/`, `tests/Sidecue.Windows.Tests/Audio/`.

Parent coverage: scope 1, 2, 3; acceptance 1, 2, 3; validation 1.
